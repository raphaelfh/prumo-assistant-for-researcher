# ADR-0017 — prumo-MCP local e reconciliador que propõe marcas

- Status: aceito
- Data: 2026-07-24
- Origem: Fase 3 do spec "Round-trip de revisão docx ↔ CriticMarkup" (2026-07-05, aprovado), planejada em `docs/superpowers/plans/2026-07-24-ponte-fase3-mcp-reconciliador.md`; guarda-chuva zero-friction (2026-07-22, aprovado) — decisão D0, superfície-alvo Claude Desktop/Cowork; precedente direto: ADR-0016

## Contexto
A Fase 3 da ponte docx↔CriticMarkup fecha o ciclo de revisão com um agente reconciliador. O transplante determinístico das fases anteriores (ADR-0016) resolve a maioria das mudanças de coautor, mas deixa um resíduo ambíguo — eventos `unanchored-mark`, `ambiguous-anchor` e `non-identity-span` em `events.yaml` — que só alguém lendo `review.md` linha a linha, com o contexto real ao redor, consegue fechar. O guarda-chuva zero-friction já travou D0: a superfície-alvo do pesquisador não-programador é Claude Desktop/Cowork, consumindo o plugin pelo mesmo `marketplace.json` de sempre; nessa superfície não há terminal para rodar `prumo write review events` na mão, então um agente só enxerga o ciclo de revisão através de um servidor MCP local do próprio plugin. Faltava uma fachada que exponha esse ciclo (status, eventos, worklist) e, mais delicado, um caminho para o agente propor uma resolução sem virar um segundo escritor de fato da página — o que quebraria a mecânica "código garante, agente propõe, humano decide" que rege o pacote desde antes desta ponte.

## Decisão
A dependência nova é `mcp==1.28.1` (SDK oficial, FastMCP), pinada em `pyproject.toml` como a primeira dependência de servidor do pacote. `src/prumo_assist/mcp_server.py` vive no TOPO do pacote — nunca em `domains/`, porque é a própria fachada do protocolo — e instancia `FastMCP("prumo-review")` com quatro tools: três read-only (`review_status`, `review_events`, `review_worklist`), fachadas finas que resolvem `reviews/<slug>/` pelo mesmo path resolution do `ingest()` e devolvem sempre dado plano (nunca objeto de domínio); e uma de escrita, `propose_prose_edit`, a ÚNICA tool que grava algo. O comando `prumo mcp serve` (Typer raiz) inicia o transporte stdio (`run_stdio()`), registrado em `.mcp.json` e consumido por agent-hosts (Claude Code/Desktop). Uma proposta nunca é uma escrita nova de fato: é uma marca CriticMarkup PENDENTE inserida no worklist `review.md`, com a MESMA âncora de autor que já existe para coautores humanos — `{>>prumo-autor: <autor><<}`, autor padrão `agente` — decidida pelo MESMO `apply_review` humano (`--by-author agente`) que já decide qualquer outra marca, sem nenhuma lógica de aplicação nova. A ferramenta de proposta recusa, hard-fail, ANTES de escrever, na mesma disciplina que ADR-0016 fixou para conservação de citação no export: âncora que não ocorre exatamente uma vez no corpo do worklist; payload (`a`/`b`) que cunha citekey ou sintaxe de citação (I3b); âncora que intersecta ou tangencia um span `[[@citekey]]` (I1 — tangência conta como recusa, não só sobreposição); `author` fora de uma allowlist de caracteres simples (letras, dígitos, espaço, ponto, hífen, underscore); e, depois de montar o corpo novo e antes de gravar, um round-trip guard que reparseia o resultado e reprova qualquer divergência de contagem de marcas, de identidade da marca inserida — `kind` restrito a `ins`/`del`/`sub`, nunca `comment`, que não é pareável por autor — ou de conservação do multiconjunto de citações simulando o aceite da proposta. Sem MCP conectado, ou sem o CLI `prumo` instalado no consumidor do plugin — o mesmo modo degradado já aceito para o `qmd` —, o reconciliador cai para checklist: `prumo write review events --checklist` lista os mesmos eventos em pt-BR com a ação por kind, sem propor nada. A skill `review-reconcile` orquestra esse fluxo com escopo de ferramentas restrito a `Bash(prumo write review events *)` e `Bash(prumo doctor *)`, leitura de arquivos (Read/Glob/Grep) e as quatro tools MCP, propondo mas nunca decidindo — eventos de citação (`citation-touched-prose`, `citation-drop`) vão sempre para o humano, sem exceção.

## Consequências
O agente vira útil sobre o resíduo ambíguo do transplante sem se tornar confiável-por-obrigação: toda proposta passa pelas mesmas guardas de conservação de citação e pela mesma decisão humana de qualquer marca manual, então um agente hostil ou confuso no máximo propõe marcas descartáveis — nunca aplica nada sozinho. O custo é permanente: o pacote ganha sua primeira dependência de servidor (`mcp==1.28.1`) e uma superfície de protocolo — 4 tools, 1 delas de escrita — que passa a exigir versionamento e disciplina de compatibilidade como qualquer outra interface pública; e o consumidor do plugin sem o CLI instalado vê o servidor `prumo-review` falhar ao subir, aceitável porque o fallback por checklist continua funcionando e o mesmo trade-off já vale para o `qmd`. Concretamente, esse versionamento ainda não existe: `serverInfo.version` no handshake MCP reporta a versão do SDK (limitação do FastMCP 1.28.1, que não expõe parâmetro de versão de aplicação), `review_events` devolve a lista de eventos sem o envelope `schema_version` que o `--json` do CLI carrega, e `review_status` é um dict ad-hoc sem schema versionado — estabilizar os três fica para a Fase 4.
